# Assumptions

> Each assumption is documented the moment it is made. Format: **What** — Why — Where in code.

| # | What | Why | Where |
|---|---|---|---|
| A1 | Prescription validity window defaults to 6 months from the date on the prescription | Spec says configurable with a default; 6 months is common in Indian pharmacy practice | `src/domain/assert-dispatchable.ts`, config constant |
| A2 | `generic_substitutes` is an invented lookup table linking brand products to generic equivalents | Spec §5.5 calls this an ASSUMPTION; no real formulary data | `prisma/schema.prisma`, `GenericSubstitute` model |
| A3 | Pincode-to-lat/lng is a small seeded lookup table (~20 Kolkata pincodes), not a geocoding API | Spec §5.6 calls this an ASSUMPTION; avoids external dependency | `prisma/schema.prisma`, `PincodeCoord` model; `seed.ts` |
| A4 | Hindi and Bengali UI strings are translations reviewed for consistency; neutral AI draft terminology used | AI-generated translations may have minor phrasing nuances; required honest disclosure | `messages/hi.json`, `messages/bn.json`, `messages/en.json` |
| A5 | All prescription images in seed data are SYNTHETIC (invented names, not real prescriptions) | Free-tier AI inputs may be used for training; spec §6 requires this | `seed/prescriptions/`, `scripts/generate_prescriptions.py` |
| A6 | Upload size limit is 5 MB per prescription image; accepted MIME types are image/jpeg and image/png | Reasonable mobile photo size; spec doesn't specify exact limit | `src/lib/validators/upload.ts` |
| A7 | OTP rate limit: max 5 attempts per phone per 15 minutes; login rate limit: max 10 per phone per hour | Spec says rate-limited but doesn't specify exact numbers; these are industry-reasonable | `src/lib/auth/otp.ts` |
| A8 | Haversine distance is sufficient for Kolkata store routing (no road network/traffic) | Spec says "nearest store (haversine)"; city scale makes haversine acceptable | `src/domain/routing.ts` |
| A9 | Stock CSV columns: `store_id`, `product_id`, `quantity` — validated by Zod per row | Spec says "daily stock CSV import" but doesn't define format | `src/lib/validators/stock-csv.ts` |
| A10 | Refill reminder default is 5 days before run_out_date | Spec §5.7 states this default | `src/domain/refill.ts` |
| A11 | Demo/seed pharmacist registration numbers are synthetic (e.g., "WB/PHARM/2024/0001") | Spec forbids real registration numbers | `prisma/seed.ts` |
| A12 | Session cookie uses HS256 with a server-side secret (`SESSION_SECRET` env var) | jose supports multiple algorithms; HS256 is simplest for a monolith | `src/lib/auth/session.ts` |
| A13 | Customer self-registration is supported for real customers; unseeded numbers create User, CustomerAddress, and FamilyProfile | Allows any reviewer or real customer to test with their own number; role is strictly constrained to CUSTOMER | `src/app/login/page.tsx`, `src/app/api/auth/register/route.ts` |
| A14 | Family profile creation defaults to "Self" upon registration; additional profiles can be added | Core reordering flow works out-of-the-box for newly registered users | `src/app/api/auth/register/route.ts` |
| A15 | Payments support two honest paths: Path A (Razorpay sandbox gateway) and Path B (Direct UPI Transfer demo) | Spec requires real sandbox gateway with HMAC-SHA256 signature verification (Path A). Path B provides direct transfer via `upi://pay` URI & genuine QR code, requiring explicit staff manual verification | `src/lib/payments/gateway.ts`, `src/app/api/payments/` |
| A16 | The app name "MedKart" is invented for this project; not a real brand | Needs a name for UI; spec doesn't specify one | Throughout UI |
| A17 | Schedule H1 register date (h1Date) records the prescription issue date confirmed by pharmacist | Drugs & Cosmetics Rules require date of prescription on register; defaults to verified prescriptionDate | `src/app/api/pharmacist/orders/[id]/verify/route.ts` |
| A18 | Non-generative OCR pipeline: Zero generative LLMs used in perception or extraction | Prescriptions require perception/extraction, not creative generation. Generative LLMs hallucinate non-existent drugs under uncertainty. A small vision OCR model + deterministic regex and fuzzy matching is honest and clinically safe. | `src/lib/ai/hf-ocr-reader.ts`, `src/lib/ai/deterministic-parser.ts` |
| A19 | Three-Tier OCR Architecture & Vercel Serverless Limits | Tier 1 uses hosted small model (`microsoft/trocr-base-handwritten`) via `router.huggingface.co`. Tier 2 runs locally in-process via `tesseract.js` (WASM). Vercel Hobby serverless has a 250MB bundle and 15s timeout limit; Tesseract WASM cold starts take 4–8s on serverless, so Tier 1 is primary in cloud, Tier 2 in local/Docker, and both fall back safely to Tier 3 manual queue without crashing. | `src/lib/ai/hf-ocr-reader.ts`, `docs/deployment.md` |
| A20 | Measured Tier 1 Confidence Proxy: No Fabricated Constants | Hugging Face TrOCR Inference API returns strictly `{ generated_text: string }` without per-token probabilities. To eliminate invented constants honestly, Tier 1 computes a deterministic lexical sanity proxy: $C = 0.35 \times S_{alnum} + 0.30 \times S_{entropy} + S_{med}$. Anything $< 0.45$ falls through to Tier 2/Tier 3. | `src/lib/ai/hf-ocr-reader.ts` |
| A21 | Real OCR Image Legibility Statistics: $W_{mean} \ge 0.65$ (clear), $0.40 \le W_{mean} < 0.65$ (partial), $< 0.40$ (unreadable) | Prevents guessing legibility. Low word confidence or unreadable scans automatically route to pharmacist queue. Observed test latency: 714–1099ms in Node.js. | `src/lib/ai/deterministic-parser.ts`, `scripts/test_real_ocr.ts` |
| A22 | Honest OTP Delivery: On-screen demo SMS banner exclusively for allowlisted demo accounts (`DEMO_PHONES`), real SMS dispatched when `SMS_PROVIDER` configured | Free-tier SMS providers (MSG91/Twilio trial) reject unverified trial numbers with HTTP 400/403. Real SMS is attempted for non-demo numbers (failing with 503 if unconfigured), while the on-screen demo banner is strictly restricted to allowlisted demo accounts in `DEMO_MODE=true`. | `src/lib/auth/otp.ts`, `src/lib/auth/otp-providers/` |
| A23 | Direct UPI Payment (Path B) Never Auto-Marked Paid | Direct UPI payments generate real `upi://pay?pa=...&pn=...` URIs and dynamic QR codes via `qrcode` package using the configured `UPI_PAYEE_VPA` env var. When `UPI_PAYEE_VPA` is unset, Path B is completely hidden. The order is stored with `paymentMethod = 'DIRECT_UPI'` in `PAYMENT_PENDING_VERIFICATION` status until store staff or pharmacist explicitly verifies the transaction UTR in `orderAudit`. | `src/app/customer/order/new/page.tsx`, `src/app/api/payments/confirm-manual/route.ts` |
| A24 | Session Revocation & Versioning via `tokenVersion` | User JWTs contain a `sessionVersion` claim matching `User.tokenVersion` in PostgreSQL. Triggering "Sign Out of All Devices" increments `tokenVersion`, instantly invalidating existing JWT sessions across all browsers. | `src/lib/auth/session.ts`, `src/app/api/auth/logout-all/route.ts` |
| A25 | Pure EXIF/GPS Metadata Stripping & Magic-Byte Validation | To ensure patient privacy under the DPDP Act 2023 without bulky native C++ image libraries, JPEG APP1 and WebP EXIF chunks containing GPS coordinates and camera serials are stripped at the raw byte level upon upload. True magic bytes (JPEG `FF D8 FF`, PNG `89 50 4E 47`, WebP `RIFF....WEBP`) are verified before processing. | `src/lib/validators/upload.ts` |
| A26 | DPDP Act 2023 Prescription Access Audit Logging | Any route decrypting or streaming prescription photos writes an append-only row to `PrescriptionAccessLog` capturing viewer ID, user role, order ID, and SHA-256 hashed IP address. | `src/app/api/prescription/[id]/image/route.ts` |
| A27 | Store Handover & Delivery Fulfillment Lifecycle | Orders packed by store staff transition to `HANDED_OVER` when picked up by courier (recording courier name and tracking number), and to `DELIVERED` upon final drop-off. | `src/app/api/store/orders/[id]/handover/route.ts`, `src/app/api/store/orders/[id]/deliver/route.ts` |
| A28 | Refund Due Operations Queue (`REFUND_DUE`) | Orders paid online via Payment Gateway or Direct UPI that are subsequently rejected or cancelled enter `REFUND_DUE` status. Ops managers review and disburse refunds with transaction references via `/api/ops/process-refund`. | `src/app/api/ops/process-refund/route.ts`, `src/lib/orders/order-state.ts` |
| A29 | Public Product Catalogue Gating | When `PUBLIC_CATALOGUE_OTC_ONLY=true` is configured, unauthenticated requests to `/api/products` are strictly restricted to `schedule = 'OTC'`. Authenticated users or explicit query filters access the full formulary. | `src/app/api/products/route.ts` |
